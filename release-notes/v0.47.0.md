# v0.47.0 – Upload: state compact (loading / completed / download / reupload / validation error)
วันที่: 2026-11-23

## เพิ่มใหม่
- `aibox-upload-file` (บน `nz-upload` ที่ **ไม่มี** drop zone + `[nzFileList]`): ไฟล์ในกล่อง compact ตาม Figma Upload state loading compact (`3954:4149`), completed compact (`3889:800`), completed with download (`8066:6395`) และ validation error (`3919:1197`): กล่อง 480 x 69px (error 72px) กรอบ 1px solid `border/secondary` (แดง `text/status/error/100` ตอน error) มุม 8px แถวไฟล์อยู่ห่างขอบ 10px: กล่องไอคอน 24px (วงกลมหมุนในกล่อง 32px) ชื่อ 16/26 medium สี `color/main` ช่องไฟ 8px และปุ่มลบ 32px ใส่ `showDownloadIcon: true` จะได้ปุ่มดาวน์โหลด 32px ก่อนปุ่มลบ (ต้องลงทะเบียนไอคอน `DownloadOutline`) ข้อความผิดพลาดใช้ `.aibox-upload-error-text` ใต้กล่อง (ห่าง 10px รวมสูง 106px ตรงกับ Figma)
- `aibox-upload-file-invalid`: validation error with download (`8070:6712`) ng-zorro แสดงปุ่มดาวน์โหลดเฉพาะไฟล์ `done` ไม่แสดงให้ `error` ไฟล์ที่อัปโหลดแล้วแต่ไม่ผ่านการตรวจจึงเป็นไฟล์ `done` + class นี้ (กล่อง ไอคอน ชื่อ ปุ่มสีแดงสูง 72px)
- state reupload (`4190:855`): ปุ่ม texted ขนาด small "อัปโหลดใหม่" ไม่ใช่ส่วนของแถวไฟล์ของ ng-zorro จึงเป็น `nz-upload` ตัวที่สองข้างกล่อง ใน `<div class="aibox-upload-file-reupload">` ปุ่มใช้ class `aibox-upload-file-action` อยู่ก่อนปุ่มลบ 8px (ไอคอน 12px ในกล่อง 16px ช่องไฟ 4px สูง 32px; ต้องลงทะเบียน `UploadOutline` และซ่อนปุ่มดาวน์โหลดใน state นี้)
- เว็บเอกสาร: demo "Compact file box" (6 state) และแถวคลาสใหม่ 3 แถวในหน้า Getting started ลงทะเบียนไอคอน `DownloadOutline` / `UploadOutline` ใน `app.config.ts`

## แก้ไข
- v0.46.0 `aibox-upload-inline`: แถวสถานะกำลังอัปโหลดใช้กล่องไอคอน 32px (Figma: ชื่อไฟล์เริ่มที่ 40px) เดิมใช้ 24px (ชื่อเริ่มที่ 32px) สถานะอื่นยัง 24px

## ข้อควรรู้
- `nz-upload` ที่ไม่มี drop zone ยังสร้าง element เลือกไฟล์ว่างสูง 22px เหนือรายการ `aibox-upload-file` ซ่อนไว้ (ไม่มีอะไรให้คลิก) กล่องจึงอยู่ที่ตำแหน่งแรกของ container
- ng-zorro เก็บค่าการแสดงปุ่มดาวน์โหลด / preview ไว้ในออบเจ็กต์ไฟล์ ถ้าใช้อาร์เรย์ไฟล์เดียวกันกับ `nz-upload` หลายตัวที่ตั้ง `nzShowUploadList` ต่างกัน ค่าจะปนกัน ให้ใช้อาร์เรย์แยกต่อ `nz-upload`
- Figma วาดแถวไฟล์ของ loading / completed สูง 29px (เนื้อหา 32px ล้นออก) ทำให้กล่อง compact สูง 69px ส่วน validation error แถวสูง 32px กล่องจึงสูง 72px ใช้ตามตัวเลขของ Figma (69px / 72px) ไอคอนใช้ 16px ทุกสถานะ (Figma วาด 20px ใน loading / completed)

## ตรวจแล้ว
- วัดใน DOM จริงบน ng-zorro-antd 18.2.1, 19.3.1, 20.4.4, 21.3.3 และ 22.1.2 (แอปเล็ก) ได้ค่าเท่ากันทั้ง 5 เวอร์ชันทั้ง 6 state: กล่อง 480 x 69 (error 72), กรอบ `rgb(187, 190, 196)` (error `rgb(240, 69, 66)`), มุม 8px, กล่องไอคอนเริ่มที่ 10px, ชื่อเริ่มที่ 50px (loading) / 42px (อื่นๆ), ปุ่มลบชิดขอบขวา 10px, ปุ่มดาวน์โหลดที่ x=398, ปุ่ม "อัปโหลดใหม่" สูง 32px (padding 16px, ช่องไฟไอคอน 4px) อยู่กลางแถวห่างขอบขวา 50px, ข้อความผิดพลาดห่างกล่อง 10px รวม 106px
- เว็บเอกสาร (22.1.2) ฟอนต์ไทยจริง: ตรงกับ Figma ทุก state
- `npm test` ผ่าน (846 token)
